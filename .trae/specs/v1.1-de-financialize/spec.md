# 人生即股票 v1.1 规格说明书

## 一、问题与目标

### 背景

v1.0 以"股票"为核心隐喻建立了人生量化模型，但存在三类问题：

1. **金融化过重、焦虑感强**："股价""股东注资""IPO上市"等术语让用户感到被估值、被评判，背离产品"激励成长"的初衷。
2. **公式口径有瑕疵**：BV 量纲不统一（除以经验常数 13000）、阶段系数阶跃式跳变、学历也被折旧、娱乐权重过低（0.3）、ROE 分母可能为 0。
3. **工程化不足**：单文件 HTML+JS，无类型系统、无单元测试、无数据导出备份、对比功能可能引发金额攀比。

### 目标（v1.1）

* **去金融化、去焦虑化**：保留"可量化成长"的隐喻，但术语温和化。

* **公式自洽**：BV 量纲统一为万元、阶段系数平滑、折旧策略区分学历与技能、ROE 分母加 1。

* **工程化升级**：TypeScript + Vite 模块化、单元测试、数据导入导出、IndexedDB/localStorage。

* **正向对比**：多用户对比只比结构不比金额，匿名化。

### 非目标

* 不做后端服务（保持纯前端）。

* 不做真实理财/投资建议。

* 不追求股价与真实资产挂钩。

***

## 三、核心公式（v1.1 修正版）

### 3.1 人生指数

```
人生指数 = (100 + BV × 阶段系数 + 里程碑加成) × 成长系数 × 质量系数 × (1 - 风险折扣)
```

* 100 = 基准指数（对应 IPO\_PRICE，所有人同一起点）

* BV = 累计成长资本（**万元**）

* 阶段系数 = 平滑插值后的人生阶段乘数

* 里程碑加成 = 已达成里程碑的加分总和

* 成长系数 = f(收入增长, 学习时长)，范围 \~\[0.8, 1.3]

* 质量系数 = f(健康分)，范围 \~\[0.6, 1.3]

* 风险折扣 = f(负债率)，范围 \[0, 0.5]

### 3.2 BV（累计成长资本，万元）

```
BV = Σ (每笔投入金额 ÷ 10000) × 类型权重 × 折旧系数
```

* 金额统一 **÷ 10000** 转为万元（**移除 NORMALIZATION\_K=13000**）

* 类型权重：education 1.5, skill 1.3, health 1.1, network 1.0, **entertainment 0.5**, other 0.5

### 3.3 折旧策略（关键修正）

| 投入类型              | 折旧策略                  | 理由                       |
| ----------------- | --------------------- | ------------------------ |
| education（学历）     | **不折旧**（halfLife = ∞） | 学历是终身资产，不因时间贬值           |
| skill（技能）         | halfLife = 5 年        | 技能需持续练习，会生疏              |
| health（健康）        | halfLife = 4 年        | 健康需持续维护                  |
| network（人脉）       | halfLife = 3 年        | 人脉需持续经营                  |
| entertainment（娱乐） | halfLife = 1 年        | 娱乐价值快速消退，但权重提至 0.5（恢复系数） |
| other             | halfLife = 2 年        | <br />                   |

折旧公式：`decay = exp(-0.693 × years ÷ halfLife)`，学历类型跳过折旧。

### 3.4 阶段系数（平滑插值）

原阶跃表改为**节点间线性插值**：

| 年龄节点 | 系数  |
| ---- | --- |
| 0    | 0.2 |
| 6    | 0.3 |
| 12   | 0.5 |
| 18   | 0.9 |
| 25   | 1.1 |
| 35   | 1.5 |
| 50   | 1.3 |
| 80+  | 0.8 |

插值：`coef(age) = lerp(node[i].coef, node[i+1].coef, (age - node[i].age) / (node[i+1].age - node[i].age))`

### 3.5 成长效率（原 ROE）

```
成长效率 = EPS ÷ (BV + 1)
```

分母 +1 避免 BV=0 时除零。仅作参考指标，不影响指数计算。

### 3.6 估值倍数（原 PE）

```
估值倍数 = 人生指数 ÷ EPS
```

仅作参考展示，标注"参考值"。

## 四、功能需求

### F1 问卷精度降级为参考区间

* 地区/家庭/学历/收入 4 问产出的历史投入为**估算区间**，不再宣称"±4%精度"。

* 文案改为"基于统计数据的参考估算，你可以通过锚点校准修正"。

* 锚点校准功能保留并强化：用户输入某年龄真实投入，系统按比例校准整条历史曲线。

### F2 计算明细页

* 新增"计算明细"入口，展示当前人生指数的完整拆解：

  * 100（基准）

  * BV × 阶段系数（含 BV 构成明细：每笔投入 × 权重 × 折旧）

  * 里程碑加成（列出每项）

  * 成长系数（收入增长、学习时长贡献）

  * 质量系数（健康贡献）

  * 风险折扣（负债贡献）

  * 最终指数 = 乘积

* 让用户理解"为什么是这个数"。

### F3 数据导入/导出 JSON

* 导出：将用户全部数据（档案+历史+投入+里程碑+挫折）序列化为 JSON 文件下载。

* 导入：上传 JSON 文件恢复数据（需校验格式）。

* 目的：备份、换机、跨设备同步。

### F4 分享卡片隐藏金额

* 分享卡片中**不显示具体金额**（BV、EPS、累计投入等数字打码或移除）。

* 仅展示：人生指数、走势趋势（↑/↓）、达成里程碑数、成长效率等级（优良中差）。

* 目的：避免金额攀比，保护隐私。

### F5 免责声明

* 首页底部、计算明细页、分享卡片均展示：

  > "本产品为个人成长量化工具，所有数值基于模型估算，不代表真实资产或投资建议。成长没有标准答案。"

* 首次进入时弹窗确认一次（localStorage 记录已确认）。

### F6 多用户匿名结构对比（P1）

* 用户可生成匿名"结构画像"（不含金额）：各投入类型占比、里程碑达成率、健康等级、学习习惯。

* 与同龄人的**结构分布**对比（如"你的教育投入占比高于 70% 的同龄人"），不对比绝对金额。

## 五、非功能需求

### NF1 技术栈迁移（P1）

* 从单文件 HTML+JS 迁移至 **TypeScript + Vite** 模块化。

* 目录结构：

  ```
  src/
    types/          # 类型定义
    engine/         # 计算引擎（pure functions，可单元测试）
    storage/        # IndexedDB/localStorage 封装
    components/     # UI 组件
    App.ts
  tests/
    engine.test.ts  # 公式单元测试
  ```

### NF2 单元测试（P1）

* 核心公式必须有单元测试覆盖：BV 计算、阶段系数插值、折旧、人生指数计算、ROE 边界。

* 使用 Vitest。

### NF3 存储

* 主存储：localStorage（保持简单）。

* 支持 IndexedDB 作为可选增强（P2）。

* 必须支持 JSON 导出作为备份手段。

### NF4 去焦虑化设计

* 指数下跌时用"调整期""蓄力期"等中性表述，不用"亏损""暴跌"。

* 色彩：下跌用中性灰/蓝，不用刺眼红色（或红色仅用于健康告警）。

* 文案避免"你落后了""跑输同龄人"，改为"还有成长空间"。

***

## 六、约束与假设

* 纯前端，无后端。

* 数据仅存本地，不上传。

* 不做真实金钱相关计算。

* 公式参数（阶段系数表、权重、半衰期）基于教育/心理学常识估算，非学术研究结论。

***

## 七、验收标准

### Rule 类

* \[R1] 全页面搜索不到"股价""股东注资""K线""IPO上市"等 v1.0 金融术语（计算明细的公式说明中允许保留"指数"）。

* \[R2] BV 计算使用 `金额 ÷ 10000`，代码中不存在 `NORMALIZATION_K: 13000`。

* \[R3] education 类型的折旧系数恒为 1（不折旧）。

* \[R4] 阶段系数在任意年龄都返回节点间的线性插值结果，无阶跃。

* \[R5] entertainment 权重为 0.5。

* \[R6] 成长效率（ROE）公式为 `EPS / (BV + 1)`，BV=0 时不报错。

* \[R7] 分享卡片不含任何金额数字。

* \[R8] 首页和分享卡片可见免责声明文案。

* \[R9] 导出的 JSON 可重新导入并完整恢复数据。

* \[R10] 计算明细页展示指数的完整拆解步骤。

### Rubric 类

* \[Rub1] 去焦虑化程度（0-2）：文案无"亏损/暴跌/跑输"等负面词，下跌用中性表述。

* \[Rub2] 公式自洽性（0-2）：BV 量纲统一、无除零、插值平滑。

* \[Rub3] 工程化程度（P1）（0-2）：TS 类型完整、核心公式有单测、模块化清晰。
